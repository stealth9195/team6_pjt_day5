# Freely 팀 작업 가이드

4명이 4개 화면을 나눠 만들어도 한 사이트처럼 보이게 하는 규칙이에요.
**뼈대·CSS 담당**이 공통 틀을 관리하고, 각 담당자는 자기 페이지 안에서만 작업해요.

## 1. 폴더 구조와 담당

```
index.html        홈(랜딩)
classes.html      클래스(제품) 화면: 클래스 종류와 목록
booking.html      예약 화면
about.html        회사소개: 오시는 길, 지도

css/
├─ tokens.css       값 (색, 글자 크기, 간격, 모서리)        ← 뼈대·CSS 담당만 수정
├─ base.css         기본 설정 (글자 기본값, 폭, 섹션 간격)    ← 뼈대·CSS 담당만 수정
├─ layout.css       머리글·바닥글 모양                      ← 뼈대·CSS 담당만 수정
├─ components.css   공통 부품 (버튼, 카테고리, 필터 칩, 카드, 입력칸 ...) ← 뼈대·CSS 담당만 수정
└─ pages/
   ├─ home.css        ← 홈 담당
   ├─ classes.css     ← 클래스 화면 담당
   ├─ booking.css     ← 예약 화면 담당
   └─ about.css       ← 회사소개 담당

js/
├─ layout.js        머리글·바닥글 내용 (메뉴 이름·순서는 여기 한 곳)  ← 뼈대·CSS 담당만 수정
├─ components.js    카테고리·필터 선택 동작                        ← 뼈대·CSS 담당만 수정
└─ home.js          홈 전용 동작                                  ← 홈 담당
```

| 페이지 | 담당 | 수정해도 되는 파일 |
|---|---|---|
| 뼈대·CSS | [이름] | tokens / base / layout / components .css, layout.js, components.js |
| 홈 | [이름] | index.html, css/pages/home.css, js/home.js |
| 클래스 | [이름] | classes.html, css/pages/classes.css |
| 예약 | [이름] | booking.html, css/pages/booking.css |
| 회사소개 | [이름] | about.html, css/pages/about.css |

※ 4명이 4개 화면을 맡고 뼈대·CSS 담당이 한 화면을 겸하는 경우, 위 표에서 그 사람의 이름을 두 곳에 적어요.

## 2. 먼저 해결할 것: .gitignore

작업 폴더의 `.gitignore`에 `*.html` 규칙이 있으면 **HTML 파일이 git에 올라가지 않아요.**
(앞서 TEST 폴더 화면에서 Claude Code가 알려준 내용이에요.) 팀원들이 서로의 페이지를 받으려면
이 규칙을 지우거나 예외 처리해야 해요. 이 파일은 팀 저장소에 맞게 한 사람이 정해서 고쳐요.

## 3. 내 작업 범위

- 내 페이지의 HTML 안쪽(`<main>` 안), 내 페이지 전용 CSS/JS만 수정해요
- 머리글(`<header id="site-header">`)과 바닥글(`<footer id="site-footer">`) 줄은 건드리지 않아요
- 다른 사람의 페이지 파일은 수정하지 않아요

## 4. 쓸 수 있는 것 / 쓰면 안 되는 것

**쓸 수 있는 것**
- `tokens.css`의 값: `var(--color-accent)`, `var(--space-m)` 같은 이름
- `components.css`의 공통 부품: `.button`, `.chip`, `.categories`, `.class-card`, `.placeholder`, `.field`, `.page-header`
- 공통 구조: `.container`(페이지 폭), `.section`(섹션 간격), `.section__title`(섹션 제목)

**쓰면 안 되는 것**
- `#색상코드`나 `px` 숫자를 직접 쓰기 (선 굵기 1~3px와 미디어쿼리 `em` 값만 예외)
- 공통 파일 수정 (바꾸고 싶으면 요청: 아래 6번)
- 확인되지 않은 정보를 사실처럼 쓰기: 후기, 수치, 가격, 주소, 강사·공방 정보, 기능
  - 모르면 `[확인 필요]`라고 적고, 샘플 화면에는 "예시"라고 표시해요

## 5. 이름 규칙

페이지 전용 클래스 이름은 **페이지이름-** 으로 시작해요. 이름이 겹쳐서 다른 페이지가 깨지는 일을 막아요.

| 페이지 | 접두어 | 예시 |
|---|---|---|
| 홈 | `home-` | `.home-hero`, `.home-step__title` |
| 클래스 | `classes-` | `.classes-grid` |
| 예약 | `booking-` | `.booking-form` |
| 회사소개 | `about-` | `.about-map` |

- 한 페이지 안에서 부분을 나눌 때는 `이름__부분` (예: `.about-info__row`)
- 두 페이지 이상에서 같은 부품을 쓰게 되면 공통 부품으로 올려요 → 요청(6번)

## 6. 공통 파일에 요청할 때

아래 3줄을 뼈대·CSS 담당에게 보내요.

```
- 필요한 것: (예: 입력칸에 오류 문구 모양)
- 쓰는 곳: (어느 페이지, 어느 부분)
- 지금 임시로 한 방법: (있다면)
```

## 7. 올리기 전 확인 (검수 체크리스트)

- [ ] 브라우저에서 직접 열어봤다 (AI가 만들었다고 확인된 게 아니에요)
- [ ] 창을 좁혀서 모바일 폭(375px 정도)에서도 깨지지 않는다
- [ ] 가로 스크롤이 생기지 않는다
- [ ] `#색상코드`와 `px` 숫자를 직접 쓴 곳이 없다 (VS Code에서 `Cmd + Shift + F`로 `#` 검색)
- [ ] 지어낸 정보가 없다 (`[확인 필요]`와 "예시" 표시를 지키고 있다)
- [ ] Tab 키로 버튼과 링크가 순서대로 이동하고, 선택된 곳이 보인다

## 8. 알아둘 점

- 머리글·바닥글은 `js/layout.js`가 만들어 줘요. 덕분에 메뉴를 한 곳에서 고치면 4개 페이지에 모두 반영돼요.
  대신 JavaScript가 꺼져 있으면 머리글이 보이지 않아요. 지금 단계에서는 감수하는 선택이에요.
- 지도(회사소개)는 어떤 서비스를 쓸지 아직 정해지지 않았어요. 서비스에 따라 키 발급 같은 준비가 필요할 수 있어요.
  (제가 서비스별 조건을 확인하지 않았으니 선택한 서비스의 공식 문서를 보세요.)

3. 필터 항목 전체와 선택지
