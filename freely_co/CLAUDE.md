# CLAUDE.md

## 1. 프로젝트 개요
- 목적: 원데이 클래스 플랫폼 Freely의 웹사이트 (HTML/CSS/JS, 외부 라이브러리 없이)
- 독자: 수강생 (클래스를 예약하는 사람)
- 독자가 하길 바라는 행동: 원하는 클래스를 빠르게 찾고, 빠르게 결정하는 것
- 브랜드 키워드: 자유로움, 가벼움, 빠름
- 핵심 메시지: [팀 확정 필요]. 임의로 만들지 않는다
- 팀: 4명이 4개 화면을 나눠 작업한다. 역할 분담과 규칙은 TEAM-GUIDE.md를 따른다

## 2. 페이지와 담당 파일
| 페이지 | HTML | 전용 CSS | 전용 JS |
|---|---|---|---|
| 홈(랜딩) | index.html | css/pages/home.css | js/home.js |
| 클래스(제품) | classes.html | css/pages/classes.css | - |
| 예약 | booking.html | css/pages/booking.css | - |
| 회사소개(오시는 길, 지도) | about.html | css/pages/about.css | - |

공통 파일 (뼈대·CSS 담당만 수정): css/tokens.css, base.css, layout.css, components.css, js/layout.js, js/components.js

## 3. 작업 범위 규칙 (가장 중요)
- 작업을 시작할 때 **어느 페이지를 작업하는지** 먼저 확인한다. 정해지지 않았으면 한 가지만 질문한다
- 지정된 페이지의 HTML(`<main>` 안), 전용 CSS, 전용 JS만 수정한다
- 다른 페이지 파일과 공통 파일은 수정하지 않는다. 필요하면 무엇이 필요한지만 알려준다
- `<header id="site-header">`와 `<footer id="site-footer">` 줄은 건드리지 않는다
- `.gitignore`는 허락 없이 수정하지 않는다. git에 올라가지 않는 문제가 보이면 알려만 준다

## 4. 디자인 규칙
- CSS의 색, 간격, 글자 크기, 모서리, 그림자, 움직임 시간은 css/tokens.css의 var(--이름)만 사용한다
- #색상코드나 px 숫자를 직접 쓰지 않는다 (예외: 선 굵기 1~3px, 미디어쿼리의 em 값). 필요한 값이 없으면 새로 만들지 말고 어떤 값이 필요한지 알려준다
- 페이지 전용 클래스 이름은 페이지 접두어로 시작한다: home- / classes- / booking- / about-
- 공통 부품(.button, .chip, .categories, .class-card, .placeholder, .field, .page-header)을 먼저 쓴다. 새 부품이 필요해 보이면 임의로 만들지 말고 제안만 한다
- CSS 로드 순서: tokens → base → layout → components → pages/<페이지>
- 포인트 색은 화면당 1~2곳만. 카테고리별 색 구분 금지 (구분은 아이콘 + 이름)
- 이미지가 없으면 임의 URL을 넣지 말고 회색 박스 + "이미지 자리"로 표시한다
- 모바일 우선. 스크롤 애니메이션은 "움직임 줄이기" 설정을 켠 사용자에게는 끈다
- 접근성: 글자·배경 대비 4.5:1 이상 목표, 이미지 alt 텍스트, 키보드 이동과 포커스 표시, 누르는 요소 최소 높이 var(--tap-min)
- CSS 주석 안에 `/* */`를 다시 쓰지 않는다 (주석이 중간에 끊겨 변수가 사라진다)

## 5. 컨셉 (홈 페이지): "클래스 찾기 여정"
스크롤하면 3단계가 펼쳐지는 여정 지도. 각 단계는 [하는 일 / 이런 마음일 수 있어요 / Freely가 해주는 일] 3줄로 통일한다.

| 단계 | 하는 일 | 마음 (가설) | Freely가 해주는 일 (확정) |
|---|---|---|---|
| 1. 찾기 | 어떤 클래스가 있나 둘러봄 | 막막함 | 카테고리 10개로 한눈에 보기 |
| 2. 좁히기 | 내 일정에 맞는 걸 추림 | 너무 많아서 지침 | 진행시간, 요일 등 필터링 |
| 3. 훑어보기 | 목록을 넘기며 후보를 봄 | 판단이 안 섬 | 스크롤로 이어서 보는 목록 |

- 위 표에 있는 기능만 소개한다. 비교, 추천, 난이도 표시, 후기 기능은 확정되지 않았으므로 어디에도 쓰지 않는다
- 마음 칸은 가설이므로 사실처럼 단정하지 않는다

## 6. 클래스 카드 (빠른 결정을 돕는 핵심)
- 카드 한 장만 보고 판단할 수 있어야 한다. 모든 카드는 같은 위치에 같은 정보를 둔다
- 카드에 담을 정보와 우선순위: [팀 확정 필요]
- 샘플 카드의 제목·진행시간·요일은 실제 데이터가 아니므로 "예시"라고 표시한다

## 7. 문구 규칙 (가장 중요)
- 말투: ~해요체, 짧고 쉬운 문장
- **지어내지 않기:** 후기, 평점, 수강생 수, 클래스 수, 공방 이름, 강사 정보, 가격, 주소, 문의 채널은 팀이 확인한 값만 쓴다. 없으면 `[확인 필요]`로 표시한다
- 가짜 후기나 실존하는 것처럼 보이는 인물 이름·사진을 넣지 않는다
- "1위", "가장 인기" 같은 최상급은 근거 없이 쓰지 않는다
- "자유롭게", "빠르게"를 쓸 때는 구체적 근거(어떤 기능인지)와 함께 쓴다

## 8. 작업 방식
- 작업 전에 이 파일과 요청을 요약해서 보여주고, 모호하면 한 가지만 질문한다
- 섹션 단위로 만들고, 끝날 때마다 바꾼 파일을 알려준다
- 브라우저에서 확인하지 않았다면 그 사실을 분명히 말한다
- 만든 뒤 style 파일에 #색상코드나 px 값이 직접 쓰였는지 검색해서 결과를 알려준다
